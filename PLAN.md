# План развёртывания почтового сервера

**Стек:** mailcow: dockerized на Debian 12  
**Масштаб:** 1 домен, до 20 почтовых ящиков  
**Цель:** полнофункциональный почтовый сервер с защитой от спама, веб-почтой и автоматическим резервным копированием

---

## Предварительная подготовка (до запуска скриптов)

### 1. Требования к серверу
- **ОС:** Debian 12 (или Ubuntu 24.04), чистая установка
- **ОЗУ:** минимум 4 ГБ, рекомендуется 6 ГБ
- **Диск:** минимум 20 ГБ свободно, рекомендуется 40+ ГБ
- **CPU:** 2+ ядра
- **Виртуализация:** KVM, Xen, VMware, выделенный сервер (не OpenVZ/LXC)
- **Сеть:** выделенный публичный IPv4, желательно с чистой репутацией

### 2. Регистрация домена
Заранее зарегистрируйте домен. Понадобятся права на изменение DNS-записей.

### 3. Снятие блокировки порта 25
Большинство VPS-провайдеров блокируют исходящий порт 25 (SMTP) по умолчанию. Напишите в техподдержку с просьбой разблокировать его. Без этого сервер сможет принимать, но не сможет отправлять почту.

**Проверка до установки:**
```bash
timeout 5 bash -c 'cat < /dev/tcp/alt1.aspmx.l.google.com/25' && echo "Порт 25 открыт" || echo "Порт 25 заблокирован"
```

### 4. Доступ к серверу
Обеспечьте SSH-доступ по ключу от имени пользователя с sudo или root. Парольная аутентификация будет отключена в процессе установки.

## Фазы развёртывания

### Фаза 0: Загрузка комплекта
```bash
# На сервере (от пользователя с sudo или root):
cd /root
git clone https://github.com/<ваш-репозиторий>/post-server
cd post-server
cp .env.example .env
chmod 600 .env
nano .env  # Заполните параметры
```

**Обязательно заполните в `.env`:**
- `MAIL_DOMAIN` — ваш домен (то, что после @ в адресах)
- `MAIL_HOSTNAME` — имя сервера, поддомен (например, `mail.example.com`)
- `ADMIN_EMAIL` — ваш email для уведомлений
- `SSH_ALLOW_USER` — имя вашего пользователя (не root)

Проверьте, что у `SSH_ALLOW_USER` есть публичный SSH-ключ в `~/.ssh/authorized_keys`.

---

### Фаза 1: Предварительная проверка
**Команда:**
```bash
sudo ./deploy/00-preflight.sh
```

**Что проверяется:**
- совместимость ОС и архитектуры
- объём RAM, CPU, диск
- публичный IP
- базовые DNS-записи (A, MX, PTR)
- занятость портов 25, 587, 993, 443
- наличие конфликтующих пакетов (postfix, exim, apache, nginx)
- доступность исходящего порта 25

**Если провалы:**
- Устраните проблемы по списку и запустите проверку повторно.
- Не переходите к установке, пока не получите ✔ все в порядке.

---

### Фаза 2: Подготовка операционной системы
**Команда:**
```bash
sudo ./deploy/10-bootstrap-os.sh
```

**Что делается:**
- обновление пакетов (apt upgrade)
- установка базовых утилит (curl, git, jq, dnsutils, ufw, fail2ban, chrony)
- настройка часового пояса и локалей
- установка имени хоста (FQDN)
- удаление конфликтующих MTA (postfix, exim, dovecot, sendmail) и веб-серверов
- освобождение порта 53 (правка systemd-resolved)
- создание swap-файла (если RAM < 6 ГБ)
- повышение системных лимитов (nofile, inotify)

**Ожидаемое время:** 3–7 минут  
**Перезагрузка:** может потребоваться, если обновилось ядро

---

### Фаза 3: Установка Docker
**Команда:**
```bash
sudo ./deploy/20-install-docker.sh
```

**Что делается:**
- подключение официального репозитория Docker
- установка docker-ce и docker-compose-plugin v2
- настройка ротации логов контейнеров (json-file: 50 МБ × 3)
- включение службы в автозапуск

**Ожидаемое время:** 2–5 минут

---

### Фаза 4: Установка mailcow
**Команда:**
```bash
sudo ./deploy/30-install-mailcow.sh
```

**Что делается:**
- клонирование репозитория mailcow-dockerized в `/opt/mailcow-dockerized`
- генерация конфигурации `mailcow.conf` (hostname, порты, IPv6, Let's Encrypt)
- настройка под доступную память (отключение Solr/ClamAV при RAM < 6 ГБ)
- загрузка Docker-образов (~2–4 ГБ)
- запуск стека контейнеров (nginx, postfix, dovecot, mysql, redis, rspamd, sogo, acme и др.)
- ожидание готовности веб-интерфейса (генерация БД и сертификата занимает 5–10 минут)

**Ожидаемое время:** 10–20 минут (зависит от скорости интернета)

**Учётные данные по умолчанию:**
- Веб-панель: `https://<MAIL_HOSTNAME>/`
- Логин: `admin`
- Пароль: `moohoo`

**ОБЯЗАТЕЛЬНО:** сразу после установки смените пароль администратора в веб-панели (System → Administrator).

---

### Фаза 5: Первичная настройка
**Команда:**
```bash
sudo ./deploy/40-postinstall.sh
```

**Предусловие:** создан API-ключ в веб-панели (Configuration → Access → API):
- Read-Write доступ
- Разрешить IP: `127.0.0.1`
- Активировать
- Вписать ключ в `.env` как `MAILCOW_API_KEY=...`

**Что делается:**
- добавление почтового домена через API
- создание первого почтового ящика (логин берётся из `FIRST_MAILBOX_LOCAL`)
- генерация DKIM-ключа (селектор `dkim`, 2048 бит)
- сохранение учётных данных в `/root/mailstack-credentials.txt` (права 600)

**Ожидаемое время:** 1 минута

---

### Фаза 6: Генерация DNS-записей
**Команда:**
```bash
sudo ./tools/gen-dns-records.sh
```

**Что получаете:**
Полный набор DNS-записей для внесения у вашего регистратора:
- **A** — адрес почтового сервера
- **MX** — куда доставлять почту для домена
- **SPF** — кто имеет право отправлять от имени домена
- **DKIM** — криптографическая подпись писем
- **DMARC** — политика обработки подделок
- **PTR** — обратная запись (настраивается в панели VPS, а не в DNS)
- **autodiscover/autoconfig** — автонастройка клиентов
- **SRV** — подсказки о портах

Записи сохраняются в файл `dns-records-<домен>.txt` с подробными пояснениями.

**Срок распространения DNS:** 15 минут – 48 часов (обычно 30 минут)

**Проверка после внесения:**
```bash
sudo ./checks/20-check-dns.sh
```

---

### Фаза 7: Настройка безопасности
**Команда:**
```bash
sudo ./security/00-harden-all.sh
```

**ВАЖНО:** откройте второе SSH-подключение до запуска. Не закрывайте его до проверки нового подключения.

**Что делается:**
1. **Межсетевой экран (ufw):**
   - политика: входящие — запрет, исходящие — разрешение
   - открыты порты SSH (с ограничением частоты), 25, 587, 993, 143, 443, 80
   - правила DOCKER-USER для ограничения частоты подключений к почтовым портам

2. **Усиление SSH:**
   - смена порта (если задано в `.env`)
   - запрет входа root (или только по ключу)
   - отключение аутентификации по паролю (только ключи)
   - современные криптоалгоритмы, отключение устаревших

3. **fail2ban:**
   - защита SSH от перебора паролей (5 попыток → бан на сутки)
   - почтовые порты защищены встроенным netfilter mailcow

4. **Параметры ядра (sysctl):**
   - защита от сетевых атак (SYN-flood, IP-spoofing, ICMP-редиректы)
   - оптимизация TCP для почтовой нагрузки
   - повышение лимитов для Docker и Dovecot

5. **Автоматические обновления:**
   - установка пакетов из `*-security` репозитория ежедневно
   - ядро и Docker не обновляются автоматически (контролируемая перезагрузка)

**Ожидаемое время:** 5 минут

**Проверка после применения:**
Немедленно проверьте вход по SSH из нового окна терминала с новыми параметрами. Не закрывайте старую сессию до подтверждения работы.

---

### Фаза 8: Настройка резервного копирования
**Команда:**
```bash
sudo ./deploy/50-setup-backup.sh
```

**Что делается:**
- создание скрипта `/usr/local/sbin/mailcow-backup`
- systemd-таймер для ежедневного запуска (по умолчанию в 03:30)
- ротация: хранение за последние 14 дней
- копирование: база данных, почтовые ящики, конфигурация Rspamd, Redis, crypt-ключи

**Каталог:** `/var/backups/mailcow` (или значение `BACKUP_DIR` из `.env`)

**Запуск вручную:**
```bash
sudo /usr/local/sbin/mailcow-backup
```

**Важно:** если резервные копии хранятся на том же диске, что и данные, настройте копирование на внешнее хранилище (см. `docs/ADMIN.md`, раздел «Резервное копирование»).

---

### Фаза 9: Полная проверка
**Команда:**
```bash
sudo ./checks/00-full-check.sh
```

**Что проверяется:**
1. **Службы и контейнеры:** состояние Docker, mailcow, системные службы, использование ресурсов
2. **DNS:** корректность A, MX, PTR, SPF, DKIM, DMARC, проверка на чёрные списки
3. **Почтовый поток:** доступность портов 25, 587, 993, 443, проверка TLS-сертификата
4. **Безопасность:** открытый релей, конфигурация SSH/firewall/fail2ban, права на файлы, обновления

**Результат:** отчёт с выводом ✔ пройдено / ✘ провалы / ! предупреждения

Все провалы содержат описание проблемы и способ исправления.

**Отчёт сохраняется в:** `/var/log/mailstack/full-check-<дата-время>.txt`

## Финальные шаги (вручную)

### 1. Проверка доставки
Отправьте письмо на https://www.mail-tester.com/:
```bash
echo "Test from my mail server" | mail -s "Test" test-xxxxx@mail-tester.com
```
Замените `xxxxx` на случайную строку, показанную на сайте.

**Цель:** оценка 10/10.  
**Типичные проблемы при оценке < 8/10:**
- PTR-запись не совпадает с именем сервера
- SPF/DKIM/DMARC не настроены или не распространились
- IP в чёрных списках (проверьте https://multirbl.valli.org/)

### 2. Входящая почта
Отправьте письмо с Gmail/Yandex на `admin@<ваш-домен>` и убедитесь, что оно дошло (проверьте через веб-почту `https://<MAIL_HOSTNAME>/SOGo/`).

### 3. Настройка почтовых клиентов
Инструкция для пользователей: `docs/USER.md`

## Обслуживание

### Резервное копирование
Автоматически ежедневно. Проверить статус:
```bash
systemctl status mailcow-backup.timer
journalctl -u mailcow-backup -n 50
```

Восстановление:
```bash
sudo ./tools/restore.sh
```

### Обновление mailcow
```bash
sudo ./tools/update-mailcow.sh
```
Создаёт резервную копию, затем обновляет стек.

### Добавление почтового ящика
```bash
sudo ./tools/add-mailbox.sh ivan "Иван Петров" 5120
```

### Мониторинг
Периодически запускайте:
```bash
sudo ./checks/00-full-check.sh
```

## Траблшутинг

### Письма не доставляются
1. `sudo ./checks/20-check-dns.sh` — проверить DNS
2. Проверить очередь: `cd /opt/mailcow-dockerized && docker compose exec postfix-mailcow postqueue -p`
3. Журнал: `docker compose logs postfix-mailcow | tail -100`

### Контейнер не запускается
```bash
cd /opt/mailcow-dockerized
docker compose ps              # состояние
docker compose logs <имя>      # журнал
docker compose restart <имя>   # перезапуск
```

### Забыт пароль администратора
```bash
cd /opt/mailcow-dockerized
docker compose exec mysql-mailcow mysql -u mailcow -p<пароль_из_mailcow.conf> mailcow \
  -e "UPDATE admin SET password='{SSHA256}...' WHERE username='admin';"
```
(см. детали в `docs/RUNBOOK.md`)

### IP попал в DNSBL
1. Узнать, в каком списке: https://multirbl.valli.org/
2. Перейти на сайт списка (например, spamhaus.org)
3. Запросить удаление (обычно доступна self-service форма)

## Дальнейшее развитие

### Дополнительные домены
1. Добавьте домен через веб-панель (Configuration → Mail setup → Domains)
2. Создайте DKIM-ключ (Configuration → Options → ARC/DKIM keys)
3. Сгенерируйте DNS-записи: `./tools/gen-dns-records.sh`
4. Внесите записи у регистратора

### Почтовые алиасы
Создаются в веб-панели: Configuration → Mail setup → Aliases

### Правила фильтрации (Sieve)
Настраиваются через веб-почту SOGo или протокол ManageSieve (порт 4190).

### Расширение ресурсов
Если памяти становится мало:
- увеличьте RAM на VPS
- пересоберите стек: `cd /opt/mailcow-dockerized && docker compose down && docker compose up -d`
