# Почтовый сервер на собственном VPS

Комплект скриптов для развёртывания почтового сервера **mailcow: dockerized** на **Debian 12**: деплой, настройка безопасности, полная проверка после установки и документация на русском языке.

**Рассчитан на:** 1 почтовый домен, до 20 ящиков.

---

## Что входит в комплект

| Компонент | Назначение |
|---|---|
| Postfix | приём и отправка почты (SMTP) |
| Dovecot | хранение писем, доступ по IMAP |
| Rspamd | фильтрация спама, подписывание DKIM |
| SOGo | веб-почта, календарь, контакты |
| ClamAV | антивирусная проверка вложений |
| MariaDB + Redis | база данных и кэш |
| Nginx | веб-сервер, панель администратора |
| acme-mailcow | автоматические сертификаты Let's Encrypt |
| netfilter-mailcow | защита почтовых портов от перебора паролей |

---

## Требования

- **ОС:** Debian 12 (чистая установка)
- **ОЗУ:** минимум 4 ГБ, рекомендуется 6 ГБ
- **Диск:** минимум 20 ГБ, рекомендуется 40+ ГБ
- **CPU:** 2 ядра
- **Виртуализация:** KVM, Xen, VMware или выделенный сервер (**не** OpenVZ/LXC)
- **Сеть:** выделенный публичный IPv4
- **Домен** с доступом к управлению DNS-записями
- **Разблокированный исходящий порт 25** — большинство VPS-провайдеров блокируют его по умолчанию, нужно запросить открытие в техподдержке

Проверка порта 25 до установки:
```bash
timeout 5 bash -c 'cat < /dev/tcp/alt1.aspmx.l.google.com/25' && echo "открыт" || echo "заблокирован"
```

## Быстрый старт

```bash
# 1. Загрузить комплект на сервер
git clone <адрес-репозитория> post-server
cd post-server

# 2. Заполнить конфигурацию
cp .env.example .env
chmod 600 .env
nano .env          # MAIL_DOMAIN, MAIL_HOSTNAME, ADMIN_EMAIL, SSH_ALLOW_USER

# 3. Проверить готовность сервера
sudo ./deploy/00-preflight.sh

# 4. Развернуть
sudo ./deploy/10-bootstrap-os.sh
sudo ./deploy/20-install-docker.sh
sudo ./deploy/30-install-mailcow.sh

# 5. Сменить пароль admin в веб-панели и создать API-ключ,
#    затем вписать его в .env как MAILCOW_API_KEY
sudo ./deploy/40-postinstall.sh

# 6. Получить DNS-записи и внести их у регистратора
sudo ./tools/gen-dns-records.sh

# 7. Применить настройки безопасности
#    ВАЖНО: держите открытым второе SSH-подключение
sudo ./security/00-harden-all.sh

# 8. Настроить резервное копирование
sudo ./deploy/50-setup-backup.sh

# 9. Проверить результат
sudo ./checks/00-full-check.sh
```

Подробный план с пояснениями каждого шага: **[PLAN.md](PLAN.md)**

## Частые операции

```bash
# Создать почтовый ящик
sudo ./tools/add-mailbox.sh ivan "Иван Петров" 5120

# Проверить состояние сервера
sudo ./checks/00-full-check.sh

# Проверить только DNS
sudo ./checks/20-check-dns.sh

# Резервная копия вручную
sudo /usr/local/sbin/mailcow-backup

# Обновить mailcow
sudo ./tools/update-mailcow.sh

# Восстановление из копии
sudo ./tools/restore.sh

# Состояние контейнеров
cd /opt/mailcow-dockerized && docker compose ps

# Очередь отправки
cd /opt/mailcow-dockerized && docker compose exec postfix-mailcow postqueue -p
```

## Что нужно сделать вручную

Скрипты автоматизируют установку, но три вещи автоматизировать нельзя:

1. **DNS-записи** — вносятся в панели вашего DNS-провайдера.  
   Скрипт `tools/gen-dns-records.sh` выдаёт готовый список с пояснениями.

2. **PTR-запись (rDNS)** — настраивается в панели VPS-провайдера, не в DNS домена.  
   Без неё Gmail, Outlook и Яндекс будут отклонять вашу почту.

3. **Разблокировка порта 25** — запрос в техподдержку VPS-провайдера.

## Особенности реализации

**Идемпотентность.** Скрипты можно запускать повторно: существующие настройки не ломаются, выполненные шаги отмечаются в `/var/lib/mailstack/`.

**Предохранители.** Перед опасными операциями скрипты проверяют предусловия. Например, `10-harden-ssh.sh` не отключит вход по паролю, если не найдёт ни одного SSH-ключа, а `20-firewall.sh` откроет порт SSH до того, как sshd на него перейдёт.

**Docker и ufw.** Docker публикует порты контейнеров в обход ufw, вставляя правила в таблицу nat. Поэтому фильтрация трафика контейнеров вынесена в цепочку `DOCKER-USER` — systemd-служба `mailstack-docker-firewall` применяет правила после старта Docker.

**Разделение защиты.** Хостовой fail2ban охраняет только SSH. Почтовые порты защищает встроенный в mailcow контейнер `netfilter-mailcow` — дублировать его на хосте означало бы конфликт правил iptables.

**Журналирование.** Все скрипты пишут в `/var/log/mailstack/`. Отчёты проверок сохраняются отдельными файлами с отметкой времени.

## Безопасность

Файл `.env` содержит пароли и API-ключ. Права должны быть `600`, в git его коммитить нельзя (см. `.gitignore`).

После развёртывания сервер имеет:
- вход по SSH только по ключу, root отключён (при соответствующих настройках `.env`)
- запрет всех входящих подключений кроме почтовых портов, HTTPS и SSH
- ограничение частоты подключений к SMTP/IMAP на уровне iptables
- fail2ban для SSH, netfilter-mailcow для почты
- автоматические обновления безопасности ОС
- современные TLS-алгоритмы, устаревшие протоколы отключены

Проверка текущего состояния: `sudo ./checks/40-check-security.sh`

Подробности: **[docs/SECURITY.md](docs/SECURITY.md)**

## Лицензия и ответственность

Комплект предоставляется как есть. mailcow распространяется по собственной лицензии — см. [github.com/mailcow/mailcow-dockerized](https://github.com/mailcow/mailcow-dockerized).

Перед применением в продакшене протестируйте развёртывание на отдельном сервере и обязательно проверьте восстановление из резервной копии.
